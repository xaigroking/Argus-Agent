# 02 · 审计规则与验收

| 项 | 内容 |
|---|---|
| 规则集版本 | v1（草案，未在真实主机验证） |
| 适用 | systemd + auditd 2.8+ 的主流发行版 |

> **本文所有规则与数值均为设计草案。M0 的任务就是在真实主机上验证并修正它们**（见 `03-里程碑任务表.md`）。未经 M0 验证前不得用于生产。

---

## 1. 规则设计原则

| 原则 | 做法 |
|---|---|
| 只审真实用户 | 一律加 `-F auid>=1000 -F auid!=unset`，排除系统服务噪声 |
| 每条规则打标 | `-k argus_*`，便于 `ausearch -k` 检索与分类统计 |
| 先量后收 | **先用最小规则集实测日志量，再决定是否放宽**。反向操作必然撑爆磁盘 |
| 排除在前 | auditd 规则按顺序匹配，`never` 规则必须放在 `always` 之前 |

## 2. 规则集 v1

安装路径：`/etc/audit/rules.d/50-argus.rules`

```bash
## ---- 基础参数 ----
-D                              # 清空现有规则（安装时慎用，见 §2.1）
-b 8192                         # backlog 上限
--backlog_wait_time 60000       # 队列满时内核等待（而非丢事件）
-f 1                            # 审计失败时 printk 告警（2=panic，生产勿用）

## ---- 排除规则（必须在 always 之前）----
# M0 实测后按噪声来源补充，例：
# -a never,exit -F arch=b64 -S execve -F exe=/usr/bin/git

## ---- 进程执行（核心）----
-a always,exit -F arch=b64 -S execve -F auid>=1000 -F auid!=unset -k argus_exec
-a always,exit -F arch=b32 -S execve -F auid>=1000 -F auid!=unset -k argus_exec

## ---- 提权相关 ----
-a always,exit -F arch=b64 -S setuid,setgid,setreuid,setregid -F auid>=1000 -F auid!=unset -k argus_priv
-a always,exit -F arch=b32 -S setuid,setgid,setreuid,setregid -F auid>=1000 -F auid!=unset -k argus_priv

## ---- 敏感文件 ----
-w /etc/passwd          -p wa -k argus_sensitive
-w /etc/shadow          -p wa -k argus_sensitive
-w /etc/group           -p wa -k argus_sensitive
-w /etc/sudoers         -p wa -k argus_sensitive
-w /etc/sudoers.d/      -p wa -k argus_sensitive
-w /etc/ssh/sshd_config -p wa -k argus_sensitive
-w /root/.ssh/          -p wa -k argus_sensitive
-w /etc/cron.d/         -p wa -k argus_sensitive
-w /etc/crontab         -p wa -k argus_sensitive

## ---- 审计系统自身 ----
-w /etc/audit/          -p wa -k argus_selfprotect
-w /etc/pam.d/          -p wa -k argus_selfprotect

## ---- 规则锁定（放在最后）----
# -e 2                  # 启用后连 root 也需重启主机才能改规则。M0 先不开，M3 后再开
```

### 2.1 已知限制

| 限制 | 说明 | 对策 |
|---|---|---|
| `-w` 不支持通配 | 无法 `-w /home/*/.ssh/`，监控各用户 SSH 密钥目录需逐个枚举 | M0 评估：枚举现有用户 + 定期刷新，或改用 `-a always,exit -F dir=/home` 配合路径过滤 |
| `-D` 会清空其他规则 | 若主机已有其他审计用途，会被覆盖 | 安装前必须备份 `auditctl -l`；`argus rules` 需检测冲突并提示 |
| `-e 2` 不可逆 | 启用后修改规则必须重启主机 | 规则稳定（M3 之后）再启用；文档中明确告知 |
| 容器环境 | 容器内通常无法加载审计规则，事件归属宿主机 | S0 不支持容器内归因，README 需写明 |

### 2.2 执行与验证

```bash
augenrules --load          # 加载 rules.d 下的规则
auditctl -l                # 列出当前生效规则
auditctl -s                # 查看状态：enabled / lost / backlog
```

## 3. auid 核对清单（归因的生命线）

`auid` 由 PAM 在登录时注入。任一入口缺失 `pam_loginuid.so`，该入口产生的行为**全部无法归因到人**，是实践中最常见的画像盲区。

### 3.1 检查项

逐入口确认 `/etc/pam.d/` 中加载了 `pam_loginuid.so`：

| 入口 | 文件 | 必须 |
|---|---|---|
| SSH 登录 | `sshd` | 是 |
| 本地终端 | `login` | 是 |
| systemd 用户会话 | `systemd-user` | 是 |
| cron | `crond` / `cron` | 是（否则定时任务无法归因） |
| su / sudo | `su`、`sudo` | 否（auid 继承自原登录，不应重设） |

### 3.2 验证方法

每个入口分别登录后执行一条命令，检查 auid 是否为真实用户：

```bash
# 期望：auid=<你的 uid>，而非 auid=unset 或 4294967295
ausearch -k argus_exec -ts recent | grep -o 'auid=[0-9a-z]*' | sort | uniq -c
```

**判定：** 出现 `auid=unset` 或 `auid=4294967295` 即为失败，必须定位到具体入口修复后重测。

## 4. 验收项（M0 出口条件）

全部为可机器判定项。未全通过不得进入 M1。

| # | 检查项 | 命令 / 方法 | 通过标准 |
|---|---|---|---|
| 1 | 审计子系统启用 | `auditctl -s` | `enabled` 为 1 或 2 |
| 2 | **无事件丢失** | `auditctl -s` | `lost` 持续为 0。非 0 说明 backlog 不足或消费太慢 |
| 3 | backlog 未逼近上限 | `auditctl -s` | 峰值 `backlog` < 上限的 50% |
| 4 | 规则全部加载 | `auditctl -l` | 与 `50-argus.rules` 条目一致 |
| 5 | **auid 覆盖率** | §3.2 | 所有入口均无 `unset` |
| 6 | **日志量实测** | 典型负载跑满 24h，量 `/var/log/audit/` 增长 | 记录日均 MB 数，据此定保留期与磁盘配额 |
| 7 | 性能影响 | 对比开启前后的基准任务耗时 | 记录实测值；劣化超 5% 需收紧规则 |
| 8 | **普通用户无法干扰** | 以无 sudo 用户尝试：停服务、读日志、改规则、删日志 | 全部失败，**且每次尝试都在审计中留下记录** |
| 9 | 日志轮转不丢事件 | 触发 `logrotate`，核对序列号连续性 | 无缺口 |
| 10 | argus 用户可读日志 | 以 `argus` 身份读 `audit.log` | 成功（ACL 或 log_group 方案任一） |

### 4.1 关于第 6 项

**日志量是本项目最大的落地风险。** 全局 execve 审计在繁忙主机（CI runner、构建机）上可产生数 GB/天，拖慢系统并撑爆磁盘。

M0 必须量出真实数字，再据此决定：

- 是否需要补充 `never` 排除规则
- `max_log_file` / `num_logs` / `space_left_action` 怎么设
- 保留期多长（直接影响 SQLite 可重建的时间窗，见 `01-方案与架构.md` §3.3）

### 4.2 auditd.conf 建议值（M0 验证）

```ini
log_format = ENRICHED          # 附带 uid→name 等解析信息
flush = incremental_async
max_log_file = 100             # MB
num_logs = 10
max_log_file_action = ROTATE
space_left = 500               # MB
space_left_action = SYSLOG
admin_space_left_action = SUSPEND
disk_full_action = SUSPEND     # 不用 HALT，避免审计问题导致主机宕机
```

## 5. 日志完整性

本机 root 仍可删除本地日志。对抗手段：

1. 日志**实时外送**至被监控者无权访问的中心节点（M4）
2. 以**"某主机日志断流"本身作为高优先级告警** —— 这是对抗本机篡改的核心信号
3. 中心侧只追加，独立保留策略与访问控制

S0 单机阶段不具备此保障，README 必须写明。
