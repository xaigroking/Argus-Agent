## 1. 部署形态（已定）

### 1.1 运行形态：systemd 服务

不是可选项。需要开机自启、需要在正确的权限域下运行、需要普通用户杀不掉。

| Unit | 运行身份 | 职责 |
|---|---|---|
| `argus-parse.service` | `argus` | 读日志、解析、归因、入库 |
| `argus-serve.service` | `argus` | 只读库、本地 HTTP |

`argus rules` 仅在安装/更新规则时以 root 执行，不常驻。

建议的 unit 加固项（🚧 M1 补具体配置）：
`Restart=always`、`NoNewPrivileges=yes`、`ProtectSystem=strict`、`PrivateTmp=yes`、`ReadWritePaths=` 仅限数据目录。

### 1.2 安装方式：不用 `curl | bash`

**理由：这是安全审计工具，安装动作需要 root。让用户把未经校验的远程脚本管道进 root shell，与本项目要解决的问题自相矛盾，也过不了任何安全团队的评审。**

优先级：

| 方式 | 阶段 | 说明 |
|---|---|---|
| 1. `.deb` / `.rpm` 包 | 🚧 M3+ | 签名、可校验、可回滚、卸载干净 |
| 2. **离线 tar + `install.sh` + `sha256`** | 🚧 M3（首选交付形态） | 下载 → 核对校验和 → 人可先读一遍 → 执行 |
| 3. `curl \| bash` | 不提供 | 仅在文档中说明为何不提供 |

Go 单静态二进制使安装只有三步：放一个文件到 `/usr/local/sbin`、装 unit、下发审计规则。

## 2. 前置条件

| 项 | 要求 | 备注 |
|---|---|---|
| 内核 | 启用 audit 子系统 | 绝大多数发行版默认启用 |
| auditd | 2.8+ | 由发行版包管理器安装，本项目不打包 |
| 架构 | x86_64 / arm64 | 📌 M0 确认 |
| 权限 | 安装需 root；运行不需要 | |
| 容器 | **不支持容器内部署** | 容器通常无法加载审计规则 |

## 3. 安装步骤

```sh
tar xzf argus_v0.1.0_linux_amd64.tar.gz
cd argus_v0.1.0_linux_amd64
sudo ./install.sh
```

`install.sh` 依次完成：检查 Linux/systemd/auditd → 创建 `argus` 系统用户（无登录 shell、
无家目录）→ 安装二进制到 `/usr/local/sbin` → 写入默认配置（已存在则保留）→
**设置 auditd 的 `log_group = argus`** 使解析服务可读日志（ACL 会在日志轮转后失效，
`log_group` 不会）→ 备份并下发审计规则 → 重启 auditd → 安装启动 systemd 服务 →
运行 `argus verify`。

参数：`--no-start` 只安装不启动；`--no-rules` 不下发审计规则（自行管理规则时用）。

📌 `log_group` 方案与 auditd 重启方式尚未在真实主机验证，这是 M0 的任务之一。

**第 5 步须先备份现有规则**（`auditctl -l > backup.rules`）：规则文件含 `-D`，会清空主机上其他审计用途的规则。`argus rules install` 必须检测冲突并提示，不得静默覆盖。

## 4. 配置

| 路径 | 内容 |
|---|---|
| `/etc/argus/config.json` | 主配置：`audit_log`、`db_path`、`listen`、`retention_days` 等 |
| `/etc/argus/agents.json` | Agent 识别规则：`[{"name":"...","exe":["..."]}]` |
| `/var/lib/argus/argus.db` | SQLite（派生缓存） |
| `/var/lib/argus/state.json` | 读取位置（inode + offset） |
| `/etc/audit/rules.d/50-argus.rules` | 审计规则 |

全部字段都有内置默认值，配置文件是可选覆盖层。文件中未出现的字段保留默认值，
因此升级新增配置项时不需要用户手工改文件。安装脚本不覆盖已存在的配置。

格式为 JSON 而非 TOML：JSON 在标准库中，为一个安全工具少引一个依赖是值得的。

**配置兼容性约束：新增配置项必须有默认值，升级永不要求用户手工改配置。**

## 5. 升级

```sh
tar xzf argus_新版本_linux_amd64.tar.gz && cd argus_新版本_linux_amd64
sudo ./install.sh        # 幂等：保留已有配置与数据
```

或手动：停服务 → 替换 `/usr/local/sbin/argus` → `argus rules install`（幂等）→ 启动 → `argus verify`。

**数据库无需迁移。** SQLite 是派生缓存，真相源是 `audit.log`（见 `01-方案与架构.md` §3.3）。schema 变更时删库从保留期内的日志重建即可。

⚠️ 仅能重建保留期内的数据。保留期由 `02` 文档 §4.2 的 `max_log_file × num_logs` 决定。

## 6. 排障（🚧 随实际问题积累）

| 现象 | 排查 |
|---|---|
| 看不到任何事件 | `auditctl -s` 的 `enabled`；`auditctl -l` 规则是否加载；`argus` 用户能否读 `audit.log` |
| **部分行为无法归因到人** | `auid=unset` → 检查对应 PAM 入口的 `pam_loginuid.so`（`02` 文档 §3） |
| `auditctl -s` 的 `lost` 持续增长 | backlog 不足或消费太慢：调 `-b`，或补 `never` 排除规则 |
| 磁盘增长过快 | 对照 M0 实测基线；补排除规则；调 `max_log_file` / `num_logs` |
| 归因显示 `unknown` | ppid 链断裂且 cgroup 锚点不一致——预期行为，不猜测 |
| 主机明显变慢 | 对照 M0 性能基准；收紧规则 |

## 7. 卸载

```
1. systemctl disable --now argus-serve argus-parse
2. argus rules uninstall       # 移除 50-argus.rules
3. augenrules --load
4. 删除二进制、/etc/argus、/var/lib/argus
5. 删除 argus 用户
```

⚠️ 若已启用 `-e 2`（规则锁定），**必须重启主机**才能移除审计规则。

## 8. 运维注意事项

| 项 | 说明 |
|---|---|
| 审计数据是高敏感资产 | 谁能访问看板需单独授权 |
| 单机部署无防篡改保障 | 本机 root 可删本地日志。需要完整性保障必须等 M4（外送 + 断流告警） |
| 看板默认仅本地可访问 | 如需远程访问走 SSH 隧道，**不要改绑定地址对外暴露** |
